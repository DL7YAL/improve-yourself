# Improve Yourself — Branding

## Product name

**Improve Yourself**

Use consistently. Module names may use the `Improve` prefix where already established, e.g. `Improve Analyzer`, `Improve Optimizer`, `Improve Benchmark`.

## Claim

**Make Up Your Mind.**

This is the approved concise claim for the product identity. Use sparingly. It should not compete with task-specific page headings.

The longer product philosophy remains:

> Improve Yourself doesn't tell you what to think. It helps you understand what happened.

This is explanatory copy, not a replacement logo lockup.

## Canonical brand source — FINAL

The user-supplied master artwork **`Improve-Yourself-Logo-Variante-3-vollstaendig.png`** is the authoritative visual source for the Improve Yourself brand.

This decision is final for the current product identity. Do not reinterpret, redraw, replace, or invent an alternative logo during implementation.

The defining construction is:
- an ascending four-stage progress/loading-bar symbol;
- the tallest/final bar forms the visual **`I`**;
- that `I` transitions into / begins the **IMPROVE** wordmark;
- **YOURSELF** sits below as the secondary wordmark;
- cool blue/cyan illumination and white/silver metallic lettering on the Midnight/Dark presentation.

The progress/loading metaphor is intentional: the mark visually communicates improvement and progression. It is not merely a generic bar-chart icon.

## Required logo usage

### Full brand lockup
Use the complete canonical mark where there is enough space, including appropriate application branding surfaces, Home/intro presentation, release/preview material and benchmark branding.

### Compact mark / application icon
For small surfaces, derive the compact icon from the **same canonical progress-bar / `I` construction**. Do not squeeze the full `IMPROVE YOURSELF` text into tiny icon sizes.

The compact mark is intended for:
- Windows EXE icon;
- Desktop shortcut;
- Start menu;
- taskbar/window icon;
- installer/setup icon;
- other small application identity surfaces.

Generate a proper multi-resolution Windows `.ico` from this canonical mark when packaging the application. The compact icon must remain recognizably part of the same brand, not become a separate logo.

### Improve Benchmark
Improve Benchmark belongs to the same brand family. Benchmark-map signage, benchmark UI and benchmark release material should use the same canonical progress-bar / `I` identity. A compact or horizontal lockup may be adapted to the available space, but the underlying logo construction must not be changed.

## Brand direction

The product identity is technical/performance-oriented, restrained and confident. It should not look like a cheat tool, casino UI, RGB utility or generic esports template.

Canonical visual family:
- Midnight / Metallic Blue as the standard theme;
- cool blue/cyan accent;
- blue/white/silver wordmark/icon treatment;
- dark application chrome;
- subtle metallic/reflection differences rather than self-illuminating RGB effects;
- precise, uncluttered typography.

A separately approved light, slightly blue-tinted theme may exist as an alternative accessibility/comfort presentation. It must not be mixed into the standard Midnight/Dark UI.

Old yellow/orange theme explorations, other discarded theme variants, and white subwindows inside the Dark theme are **not** visual targets.

## Asset authority and implementation rule

The canonical source artwork must be stored as a real repository asset before final packaging. Documentation alone is not a substitute for the artwork.

Until the master PNG and derived production assets are present in the repository:
- do not redraw the logo from memory;
- do not substitute another historical mockup logo;
- mark missing production artwork as `NEEDS_BRAND_ASSET` where necessary.

Once present, all derived assets (horizontal lockup, compact icon, `.ico`, installer icon, benchmark lockup) must trace back to that canonical source.

## Intro concept

Approved direction for later/final polish:
1. `IMPROVE YOURSELF` appears first using the canonical identity.
2. `MAKE UP YOUR MIND.` follows subtly, almost shadow-like.
3. transition into the application.

This is not a blocker for functional V1 consolidation unless explicitly assigned.

## Voice

- neutral
- transparent
- understandable
- analytical
- no automatic guilt/cheat verdicts
- no exaggerated promises

The UI should explain what data came from the demo, what Improve derived from it, and why a scene/result is being shown.
